## Step1

島ごとに ID (`island_id`) を割り振ってグループ化し、その後で各グループの要素数を数えて最大値を返す解法を思いついた。
上記の発想をそのまま愚直にコードに落とし込んだところ、Accept された（コードは `step1.py` 参照）。

### 計算量

**時間計算量**
- O((MN)^2)
    - grid の走査で O(MN)
    - row.count(id) で 1行の全要素 O(N) かつ 全ての行 O(M) を見るため O(MN)
    - 島の数 (`island_id`) は最悪で約 MN / 2個になるため、上記より時間計算量は O((MN)^2) となる。

```python
for id in range(2, island_id):
    area = sum(r.count(id) for r in grid)
    max_area = max(area, max_area)
```

**空間計算量**
- O(MN)
    - DFS の再帰スタック

**実行時間（概算）**
- 0.625 ~ 6.25 秒

### 所感

- 実行時間の概算は、遅い側（10^6 step/s）で見積もれば十分だろうか
- 6.25 秒は遅すぎると感じる。各グループの要素数を計算する処理を O(MN) に落とせないか
- 一旦 Accept を優先して入力データ grid を直接書き換えるコードにしてしまったため、step2 では visited を利用する実装を考えたい
- id 変数のような命名だと、予約語の可能性があるため、別の変数名を考えたい（調べたら `id()` 関数は存在した）
