## Step1

まず問題文を読んで隣接行列が頭に浮かんだ。しかし、ノード数 n は最大 2000 のため、4 * 10^6 要素を持つ疎行列を用意するのはメモリ効率が悪いと感じた。　　
代わりに隣接リストを採用し、DFS で連結成分ごとに探索していくのかなと漠然と考えたが、具体的な指針や実装方法が分からなかった。
そのため、他の人のコードを参考に実装した（コードは `step1.py` 参照）。

### 計算量

**時間計算量**
- O(n + E)
    - E = len(edges) とすると、隣接リストを作るのに O(E)
    - DFS で各ノードを最大1回見ていくので、O(n)
    - 以上より、時間計算量は O(n + E) となる。

**空間計算量**
- O(n + E)
    - graph で O(n + E)
        - graph の要素数（外側のリスト）が n
        - 無向グラフでは1辺につき両方向へ保存するため 2E 個が内側のリストに格納される
    - visited で O(n)
    - next_nodes で最大 O(n)
    - 以上より、空間計算量は O(n + E) となる。

**実行時間（概算）**
- 2 秒
    - E_max = n(n - 1) / 2（無向グラフの辺の最大数は、すべてのノード同士が接続されているとき）
    - E_max = 2000(2000 - 1) / 2 = 1999000
    - n + E_max = 2000 + 1999000
    - 10^6 step/s と仮定すると、実行時間は2秒
